# 故障定位

先记录失败阶段：导入、画布配置、运行分流、模型调用、输出映射。保留最近一次可用文件与明确改动，先比对同平台成功导出的字段，禁止反复从零猜结构。

| 现象 | 先检查 | 修复方向 |
|---|---|---|
| `OBS对象拷贝失败` | 新建身份、旧发布引用、DSL引用、模型异常配置、源模板能否原样导入 | 先用当前成功封装和兼容节点重建；不要将错误文案直接等同于文件系统故障 |
| 明明输入公文却报原文为空 | 开始、解析、判断节点的实际输入 | 当前对话进入query；若业务字段为空，添加解析或填写独立开始字段，避免只在聊天里写字段名 |
| 合法类型走异常路 | 判断的输入值、操作符、AND/OR、分支端口与目标 | 对“不在预设范围”用集合排除或解析节点valid布尔值；排除多个类型时不能用“不是A或不是B” |
| 循环体线不见或参数未配置 | if/elseIf端口、显式循环锚点、SetVariable.inputs | 按成功模板修复这些结构，而不是只改界面节点名 |
| 大模型输出为空 | 是否走到模型、真实输出字段、输入映射、流式设置、模型配置 | 先确定缺在模型输出还是下游引用，必要时单独测试固定文本输出 |
| 聚合结果为空 | 所选两个分支是否都未产出、引用是否有效、变量赋值数据处理记录 | 查看当前运行的候选实值；同一聚合组选已执行的分支输出 |
| 每轮结果相同或沿用上一条 | 每个互斥分支是否都写current_result、记录节点是否在赋值后 | 覆盖全部路径；测试“完整→不完整”和“不完整→完整”顺序 |
| 测试改动未生效 | 当前选择的智能体和运行记录、是否新会话/新版本 | 确认正在测试新文件对应草稿，不以旧聊天中的历史回复判断 |

## OBS错误的证据边界

该错误是外围导入包装信息，单凭它无法断定根因。公开参照实现中，工作流导入后会转换并上传IR；IR转换失败可能只写日志，随后发布或拷贝IR时再出现OBS复制失败。工行私有实现是否完全一致未知。

按以下顺序排查：

1. 校验原生封装、新UUID及code一致、草稿状态与旧发布版本清空。
2. 检查编译层输入：悬空变量、重复id、数组schema、循环输入输出、赋值和聚合配置、模型输出映射。
3. 检查LLM文本输出与异常分支是否兼容；默认使用已成功的无额外异常配置基线。
4. 原模板成功而新图失败时，保留可用封装，分组缩小发生变化的节点，不同时尝试多组无关修补。
5. 本地检查通过仍失败时明确说明缺少后台证据；若有管理员日志，定位`Failed to refresh ir`、IR适配异常、对象拷贝源路径和权限。不要伪称已取得后台日志或已确定OBS服务故障。

## 空输出的最小检查

`code=0`、`isSuccess=true`和`output_tokens>0`不能证明下游指定的输出字段已经绑定。调用链只列出变量赋值分支时，模型可能根本没有执行。先打开本次模型节点，逐项确认：输入确有正文、提示词引用正确、输出声明含真实正文变量、非流式设置有效，再检查下游引用。

固定“只返回测试成功”的指令应放进模型节点提示词做隔离测试；单在聊天框发这句话仍可能被前置入参校验拦截。测试后恢复业务提示词，不向最终用户暴露调试步骤。

## 验证报告措辞

说清“通过本地结构检查”“使用固定模型响应模拟通过”“用户反馈导入成功”“用户反馈真实运行符合预期”各自的范围。没有平台访问就不承诺自动发布或平台端测试成功。一次成功导入不证明所有新节点、外部插件和不同账号都可用。
