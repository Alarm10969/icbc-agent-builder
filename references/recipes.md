# 配方与新业务制作

## 公文初审

使用`document-review`配方。流程为query解析→必要校验→按类型匹配模板→模型初审→代码提取关键要素与核对清单→差异化消息→聚合→唯一结束。

支持工作请示、工作报告、工作通知、会议纪要；也识别请示/报告/通知别名。正文为空或类型不支持时直接返回异常且不调用内容初审模型。输出四个字段：公文类型、初审结论、待核对要点清单、审阅说明。关键要素另存内部变量。

在测试对话框整体发送：

```text
公文类型：工作请示
公文原文：申请采购服务器设备，预算金额25万元，计划11月上线，用于支撑项目管理系统三期开发，申请部门为科技部。
```

预期材料基本完整但需要核实立项手续和采购排期，不把未知审批状态直接判违规。再测试空正文、不支持类型、原文缺要素与模型返回非JSON；前两项必须绕开内容审阅模型。

## 批量需求核查

使用`requirements-audit`配方。真实数组循环逐条校验四个必要字段，缺失直接标信息不全，完整条目进入模型。代码汇总计数与详情，存在待优化时才调用汇总建议模型。

在测试对话框整体发送：

```json
[
  {"需求ID":"R001","需求名称":"项目驾驶舱报表展示","需求描述":"开发项目驾驶舱，展示各团队在研项目数量与变化趋势，用于管理监控。","提出部门":"科技部"},
  {"需求ID":"R002","需求名称":"权限改造","需求描述":"","提出部门":"科技部"},
  {"需求ID":"R003","需求名称":"日志查询功能","需求描述":"做一个日志页面，查询日志。","提出部门":"科技部"}
]
```

基础样例预期为3条：合规1、待优化1、信息不全1。报告分“统计汇总、逐条详情、整体优化汇总意见”三部分。R002不调用单条模型，R001/R003各调用一次，存在待优化时再调用一次汇总模型；真实模型仍需平台测试。

继续覆盖全通过、全部缺字段、重复需求ID、非对象条目、空清单、非法JSON，以及完整与不完整条目交替输入。空清单输出零条报告和提示，不触发模型。没有待优化且存在信息不全时直接给补充提示。

## 制作其他业务

1. 明确输入载体、必填字段、业务分支、是否批处理、输出契约。能由样例推断的就直接落实，不重复确认。
2. 从成功图保留相近结构，优先修改业务代码与提示词；不要为展示模块数量堆砌未验证节点。
3. 使用`icbc_workflow.py`构造字段、Code、LLM、Branch、Loop、SetVariable、Aggregation、End和连线；从原生模板复制Start和模型配置。
4. 将图写成`{"nodes":[],"edges":[],"layouts":{},"configs":{}}`，运行`build_agent.py --graph GRAPH --name NAME --output FILE`。指定`--template`时绑定新环境模型，必要时同时指定`--description`和`--prologue`。
5. 复杂流程保持一个结束节点；正常、异常输出类型一致，互斥路径先聚合。循环的每条路径都须产生一条本轮结果。
6. 使用通用结构校验器；针对新业务编写少量实际行为用例。`smoke_test.py`只适用于保持配方节点契约的两个样例，不适用于任意自定义流程。

`--recipe basic`只有开始、模型和结束，供新业务搭底板；它不自动实现任何额外审批、知识库、通知、对外发送或定时任务。添加此类功能时必须取得原生节点配置并具备相应授权。
